## Release contents

The [0.8.1 changelog](../CHANGELOG.md#081---2026-10-15) supplies both release bodies.
The publisher extracts that version's entry and pins its documentation links to
the release source, so both channel drafts explain the OS and CI changes.

| Release tag and title | Image channel | Foundation |
| --- | --- | --- |
| `finite-0.8.1` | `finite` | Bluefin |
| `finite-dev-0.8.1` | `finite-dev` | Bluefin-DX |

Recipes, image profile labels and CI jobs use those same `finite` / `finite-dev`
names. Installation assets are `finite.iso` and `finite-dev.iso`. The first
renamed generation requires fresh image and qualification evidence; historical
receipts and benchmark snapshots retain their original profile names. The exact
signed predecessor can still be installed with its historical profile label for
the upgrade phase, which verifies the new profile after the update.

The old validator constructed `finite-` + channel + version even though each
channel already included `finite`. The publisher copied that tag into the title.
New release requests, recovery and publishing use channel + version exactly once.
Duplicate prefixes, wrong versions and existing tags/drafts remain rejected.

Both variants preserve Bluefin's kernel, ZFS and other upstream modules together,
and retain Finite's installer, encrypted root, Secure Boot, SELinux integration,
Nix/Home Manager personalization and authentication additions. The separate
replacement kernel, IPU7 overlay and Next kernel updater are retired. See
[upstream foundations](upstream-kernel-variants.md) for preservation and trust policy.

## Next variant migration

`finite-next` and `finite-dev-next` receive no new builds, scans or qualification.
Their old release downloads are historical artifacts. Move to the active channel
with the same Bluefin foundation:

| Retired channel | Active replacement |
| --- | --- |
| `finite-next` | `finite` |
| `finite-dev-next` | `finite-dev` |

Follow the [installation guide's signed channel switch](installation.md), keep
signature enforcement enabled and inspect the staged deployment before rebooting.
For example, a standard Next installation switches with:

```bash
sudo bootc switch --enforce-container-sigpolicy ghcr.io/closure-labs/finite:finite
sudo bootc status
```

Use `:finite-dev` for the developer foundation, then reboot after reviewing the
staged image. These mutable update channels track promoted builds, not a frozen
v0.8.1 image. Hardware support now follows Bluefin's kernel/module pair; the former
Next/IPU7 guarantee is retired. Qualification of the active candidates does not
establish a separate legacy-Next migration or ZFS pool workload result.

## Measured caching optimizations

Repository overrides enabled inventory and whole-qualification reuse on October
15 after the new OS passed hosted qualification and measurement. Source/local
SecretSpec defaults stay false. GitHub Actions and local devenv/pass use the
declared SecretSpec profiles; release credentials retain their separate scopes.

| Eligible reuse path | Finite median saving | Finite Dev median saving |
| --- | --- | --- |
| Authenticated inventory | 6m55s (74.0%) | 13m30s (82.4%) |
| Whole qualification critical-path service | 30m29s (93.1%) | 32m21s (93.6%) |

These are per-hit observations, not daily pipeline savings or a measured
production hit rate. Inventory readers retain fresh DB updates, vulnerability
scans and current policy evaluation. Whole-qualification reuse retains exact
candidate, predecessor, source, build and context checks plus the original
24-hour deadline. Misses use fresh work; invalid evidence fails closed.
Automatic Cachix writing and DB transport remain disabled. The
[measured results and machine evidence](new-os-reuse-results.md) retain all samples.
