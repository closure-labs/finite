## Corrections and retry criteria

Nix's JSON serializer converts an attribute set containing `outPath` to that
path, which discarded the expected `drvPath` field. The
[matching upstream implementation](https://github.com/NixOS/nix/blob/2.35.2/src/libexpr/value-to-json.cc#L47-L55)
explains the failure. Evaluated metadata now uses `outputPath`; derivation,
output, duplicate and allowlist checks remain strict. Future failures retain
bounded field/type diagnostics without arbitrary evaluator values.

The DB pilot now retains failure receipts with authenticated origin, fresh DB
schema/build and a bounded metadata census. Its tentative transport allowance
is explicitly two GiB and 32 files. Hashing starts only after the census fits;
rejection prevents cache save. The first failure did not preserve actual file
counts or sizes, so whether the new allowance fits remains a hosted question.
There is no automatic increase when a bound is exceeded.

A rejected seed no longer prevents baseline and inventory-only readers from
running. DB-only readers fail before expensive setup when that seed failed;
other readers still perform fresh scans and retain their evidence. The final
comparison requires every lane and a successful matching seed, so partial
results remain diagnostics and cannot authorize adoption.

Verification now uses an isolated empty Docker store, separate socket and
private daemon with networking changes disabled. It retains startup, cleanup,
explicit warm seeding and complete-job costs, and continues validating the
immutable signed manifest/config/platform association and runtime behavior.
Owned-process cleanup, a bounded daemon log and a free-space preflight are
checked; Docker documents concurrent daemons as experimental. Host/private
engine and storage backends remain visible. A registry-pull diagnostic cannot
establish retained local build-output equivalence.

The first [reviewed branch diagnostic](https://github.com/closure-labs/finite/actions/runs/38671286362)
exposed an early readiness race: a zero-value Docker health object could arrive
before daemon startup completed. Empty health now retries within the existing
60-second deadline; populated wrong stores or backends still fail closed.
Docker 28 uses shared containerd services even with an empty endpoint setting.
Each diagnostic therefore uses distinct runtime namespaces and checks their
tasks/containers before startup and after Docker cleanup. Cold means an empty
private classic Docker image/layer/reference store; shared containerd content
and lease coldness is unproven. The shared service is never stopped or pruned.

The [next branch diagnostic](https://github.com/closure-labs/finite/actions/runs/38672627502)
also rejected a temporary path ending in `_` because containerd namespaces
cannot end in a separator. Namespace suffixes now use a hexadecimal hash of the
owned private path. Fixtures cover leading/trailing underscores and repeated
separators without weakening containerd's grammar or cleanup checks.

## Successful preparation retry

[38671283538](https://github.com/closure-labs/finite/actions/runs/38671283538)
completed all six samples and its strict comparison at
`a6b1c97a2cb34675aece0eae7f195be12840c0ca`. Authenticated receipts confirm the
same four tool output paths and closure sizes across both modes and passes.

| Median within this run | Legacy | Selective batch |
| --- | ---: | ---: |
| Complete job, including both passes and setup/artifact handling | 320 s | 42 s |
| Cold preparation | 210.96 s | 7.06 s |
| Warm preparation | 83.60 s | 2.76 s |
| Cold whole-runner received traffic | 1,469,433,795 bytes | 526,710,062 bytes |

The observed complete-job reduction was 278 seconds. Both groups included
runner images `20261004.327.1` and `20261012.334.1`; image differences and
whole-runner traffic limit causal claims. This measures credential-free
preparation, including the removal of unrelated proof realization. It does not
measure Cachix upload or later readers and cannot authorize automatic writing.

These corrections remain separate from the frozen release producer. Merge them
only after all four release workflows capture the successful producer revision.
Then repeat the bounded hosted pilots and append their authenticated results.
Credential-free writer and verification diagnostics can first run from the
explicit reviewed follow-up branch; security reuse retains its main-only guard.
Automatic Cachix writing, inventory/DB reuse and whole-qualification reuse stay
off until their own adoption evidence is complete.
